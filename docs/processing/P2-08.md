# P2-08 — Application Owner

P2-08 does not decide whether a vacancy matches a resume. Processing is the sole owner of that
decision and publishes `APPLICATION_CANDIDATE`. Application Owner consumes only the current
eligible candidate and owns the external side effect.

## Boundary

```text
Processing
  -> application_candidates
  -> ApplicationOwner
  -> ApplicantTransport port
  -> HHApplicantTransport
  -> vendored hh-applicant-tool applicant mechanics
  -> HH
```

`HHApplicantTransport` is the only CareerOPS source file allowed to import the vendored package.
The vendor remains an implementation island for authentication, session/cookies, resume lookup,
questionnaire transport, negotiation lookup and the actual applicant submission request.

The former vendored autonomous `apply-vacancies` runner and UI are removed. The vendor is not
allowed to discover vacancies for CareerOPS, score them, run an AI relevance filter or schedule
applications.

## Durable ownership

The existing `careerops_v2.application_candidates`, `applications` and `application_guards`
tables are the system of record. Claiming a fresh candidate and creating its non-expiring
`account_vacancy_v1` guard happen in one PostgreSQL transaction. The external HH call never runs
inside that transaction.

A candidate may be claimed only when all current operational checks still pass: candidate TTL,
current eligible match, succeeded Processing job, current binding version, enabled binding,
`auto_apply`, active resume and open vacancy.

## Submission safety

`preparing` and `precheck` leases that expire before submission may become `safe_failure` and be
retried. An expired `submitting` lease is different: the request may already have reached HH, so
it becomes `reconciliation_required` and is never blindly retried.

A successful transport call first becomes `submitted_unconfirmed`. Positive negotiation lookup
moves it to `submitted_confirmed`. A timeout, connection loss or server-side failure during the
submission window becomes `uncertain` and enters reconciliation. Negative reconciliation does not
prove that a retry is safe, so it remains in reconciliation rather than resubmitting.

## Questionnaire and cover letter

The transport may inspect an HH questionnaire but it does not invent answers. Missing required
questionnaire answers block automatic submission with an audit reason. A required cover letter
also blocks submission when none is configured. This keeps decision/generation policy outside the
vendored transport while preserving the existing HH mechanics.

## Audit

Every precheck, submit and reconciliation observation is written as immutable JSON under the
Application Owner prefix in `careerops-artifacts`. PostgreSQL keeps the current operational state
and S3 keeps the historical evidence.
