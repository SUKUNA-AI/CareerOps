# P2-04 — Requirements + ResumeEvidence

P2-04 преобразует нормализованные входы Processing в две воспроизводимые семантические
проекции:

```text
NormalizedVacancy
→ RequirementSet

NormalizedResume
→ ResumeEvidenceSet
```

P2-04 не принимает решение о соответствии вакансии резюме и не считает итоговый score

## Граница ответственности

P2-03 отвечает только на вопрос, доказано ли жесткое исключение

```text
KEEP
EXCLUDE_PROVEN
```

При `EXCLUDE_PROVEN` P2-04 не запускается

При `KEEP` Processing:

1. строит `RequirementSet`
2. строит `ResumeEvidenceSet`
3. публикует оба объекта как immutable content-addressed artifacts
4. публикует итоговый `P204ResultArtifact`

`KEEP` по-прежнему не означает match

## RequirementSet

`RequirementSet` сохраняет структуру требований вакансии, а не превращает текст в плоский
список навыков

Поддерживаются:

- `ALL`
- `ANY`
- `CONDITIONAL`
- `MANDATORY`
- `PREFERRED`
- `OPTIONAL`
- положительная и отрицательная polarity
- минимальный опыт в годах
- provenance до нормализованного поля или исходного text block

Например:

```text
Python или Scala
SQL
ETL от 3 лет
```

может быть представлено как:

```text
ALL
├── ANY
│   ├── Python
│   └── Scala
├── SQL
└── ETL >= 3y
```

## ResumeEvidenceSet

Evidence хранит не только упоминание технологии, но и контекст доказательства

Основные свойства:

- subject
- activity
- actor scope
- context
- polarity
- strength
- time span
- provenance

Примеры различий:

```text
Kafka в skill list
→ MENTION

Разработал Kafka consumer
→ SELF + DIRECT

Команда использовала Kafka
→ TEAM

Не работал с Kafka
→ NEGATIVE
```

Эти различия сохраняются для P2-05 и P2-06 и не схлопываются раньше времени

## Детерминизм

IDs semantic units зависят от:

- нормализованного содержания
- source provenance
- версии extraction/evidence алгоритма

Одинаковый immutable input при той же версии дает тот же `RequirementSet` или
`ResumeEvidenceSet`

Изменение `requirement_extraction_version` или `evidence_version` меняет identity результата

## Артефакты

P2-04 использует существующий `ProcessingArtifactStore`

Публикуются:

```text
FILTER_TRACE
REQUIREMENT_SET
RESUME_EVIDENCE_SET
P2_04_RESULT
```

Все артефакты content-addressed по SHA-256 и не используют mutable `latest`

`P2_04_RESULT` является checkpoint текущего runtime horizon P2-03 + P2-04 и содержит ссылки
на опубликованные semantic artifacts

## Runtime

Текущий execution path:

```text
processing_jobs
↓
ProcessingWorker
↓
P204Executor
↓
load pinned manifest
↓
load pinned NormalizedVacancy + NormalizedResume
↓
P2-03
├── EXCLUDE_PROVEN
│   └── FILTER_TRACE → P2_04_RESULT
└── KEEP
    ├── RequirementSet
    ├── ResumeEvidenceSet
    └── FILTER_TRACE → P2_04_RESULT
```

Pinned inputs проверяются по identity и checksum до передачи в business logic

## Что не входит в P2-04

P2-04 намеренно не содержит:

- Jina reranking
- evidence selection
- `MATCHED / NOT_EVIDENCED / UNKNOWN / CONTRADICTED`
- hard gates
- score bounds
- `SKIP / REVIEW / APPLICATION_CANDIDATE`

Это следующие стадии P2-05, P2-06 и P2-07
